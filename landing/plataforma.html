The platform

One layer. Three agents. A pipeline you can point to.

Booka isn't a single black box — it's three named agents, each running one stage of a credential's path from upload to cleared licence. Every step has an owner, and every claim on this page names the agent behind it.

Booka Demo See how it works

Verifier Agent

Live

Primary-source verification on every document a candidate submits — checked against the issuing institution, not just read and filed.

  1. 1

    Document received

    A passport, degree, transcript, or licence is uploaded through your branded portal.

  2. 2

    Extraction

    Every field is read and structured — name, issuer, dates, document number — not just filed as an attachment.

  3. 3

    Primary-source check

    Matched against the issuing institution's own record where one is reachable, and against the destination regulator's requirements in every case.

  4. 4

    Exceptions flagged

    Anything inconsistent — a mismatched name, an expired document, a missing apostille — goes to a human reviewer before it moves on.

  5. 5

    Cleared for submission

    A verified file is handed to the Regulator Agent. Nothing reaches a regulator until it clears here.

Regulator Agent

Live

Interfaces directly with the destination licensing authority — submission, status tracking, and resubmission if a regulator comes back with a request.

  1. 1

    Cleared file received

    Nothing arrives here until the Verifier Agent has signed off on it.

  2. 2

    Formatted per authority

    Matched to that regulator's own submission format — SCFHS, DHA and GMC don't take the same file the same way, and the agent knows the difference.

  3. 3

    Submitted

    Filed directly with the destination licensing authority under your brand.

  4. 4

    Status tracked

    Polled per authority, not left sitting in an inbox waiting for someone to check.

  5. 5

    Resolved

    Approved, or returned with a specific request the Verifier Agent can act on directly.

Trust Agent

Pilot

Manages the compliance layer around getting a verified professional into place — the part that runs after the credential clears and before they start work.

  1. 1

    Credential cleared

    The file has a licence or certificate behind it, issued by the destination regulator.

  2. 2

    Anchored

    Hashed and written to an immutable ledger, so its state on the day it cleared can always be proven.

  3. 3

    Compliance tracked

    The professional's and the employer's status are kept current — not just the document's.

  4. 4

    Placement supported

    The compliance layer around getting them into position, running behind the scenes on the same white-labeled layer as the other two agents.

One integration, three agents

You connect once, and every regulator is downstream of that single integration — the agents are how it stays that way as more authorities and more origin markets get added.
